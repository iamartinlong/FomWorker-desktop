# 会议纪要分发

把一段会议记录（录音转录 / 聊天记录 / 飞书云文档）整理成**结构化会议纪要**，并分发出去。

## 产出形状

一份纪要固定四段，缺哪段写「无」而不是省略：

1. **基本信息**：会议主题、时间、参会人（转录里有的才写）。
2. **结论 / 决议**：会上**明确达成**的事项，逐条。
3. **待办事项**：每条含 **事项 + 负责人 + 期限**。负责人或期限转录里没写的，标「待指派」「待确认」。
4. **遗留问题**：讨论了但没结论的。

## 工作流

1. **取原文**：
   - 会议记录在**飞书云文档**里 → 用 `feishu_doc_read`（给文档链接或 `document_id`）读正文；
   - 在**工作区文件**里 → 用 `read`。
   - 转录很长时，先通读再分条，不要漏掉后半段。
2. **整理**：按上面四段产出 Markdown 纪要正文。
3. **分发**（写飞书是**对外可见动作，会问人批准**，如实告知用户「等待批准」）：
   - 发布成**飞书云文档**：`feishu_doc_create`（`title` = 会议主题，`content` = 纪要正文）。
   - 用户要求写进**已有的会议台账多维表格**：先用 `feishu_bitable_list_records` 看现有字段结构，再按需写入。
4. **回报**：把纪要正文与（若已发布）文档链接一并回给用户。

## 纪律

- **不编造**：转录里没有的结论、负责人、期限一律不写，宁可标「待指派 / 待确认」。
- **不代替决策**：只整理与会者**说过**的内容，不替会议下结论、不替人拍板。
- **凭据**：纪要正文里**绝不出现明文密钥 / 令牌**；需要指代时只写环境变量名或位置。
- **语言**：除非用户另指定，用中文。
- **工具分级**：读飞书文档 / 多维表格 / 日历都是只读（不打扰）；**写飞书文档会弹审批卡**，这是设计如此，不要试图绕过。
