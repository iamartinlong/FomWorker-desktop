# 周报汇总

把**一周**的工作数据汇总成结构化周报并发布。

## 数据来源（按用户给的东西取，不要凭空找）

- **多维表格**（任务台账 / 进展表）→ `feishu_bitable_list_records`（给链接或 `app_token` + `table_id`）。一次最多 500 条；有 `pageToken` 就翻页，别只看第一页。
- **日历**（本周会议 / 日程）→ `feishu_calendar_list_events`（给日历 id；省略则用主日历）。`start_time`/`end_time` 是 **Unix 秒**，区间 <40 天。
- **工作区文件** → `read` / `grep`。

## 产出形状（五段，缺哪段写「无」而不是省略）

1. **本周概要**：3–5 句，覆盖最重要的事与结果。
2. **完成事项**：逐条（来自多维表格「已完成」状态 / 日历里已发生的会议）。
3. **进行中**：逐条 + 当前进度。
4. **下周计划**：逐条（来自待办 / 未完成项）。
5. **风险 / 阻塞**：需要上级或跨部门支持的事。

## 工作流

1. **定时间范围**：默认「本周一 00:00 至现在」，换算成 Unix 秒；用户给了范围就按用户的。
2. **取数**：多维表格先 `feishu_bitable_list_records` 看**字段名**（中文列名常见是「待办事项 / 状态 / 负责人 / 截止日期」），**按真实字段名聚合，不要假设列名**；日历按时间范围拉。
3. **整理**：按五段结构产出周报 Markdown。
4. **发布**（写飞书是**对外可见动作，会问人批准**，如实告知「等待批准」）：`feishu_doc_create`（`title` = 「<姓名/团队> 周报 <日期范围>」，`content` = 周报正文）。
5. **回报**：周报正文 +（若已发布）文档链接。

## 纪律

- **不编造**：数据里没有的事项不写；进度不明确就标「待确认」。
- **不夸大**：只写数据支持得了的结果，不替工作贴金。
- **凭据**：正文绝不出现明文密钥 / 令牌。
- **语言**：除非用户另指定，用中文。
- **工具分级**：读多维表格 / 日历是只读（不打扰）；**写飞书文档会弹审批卡**，这是设计如此，不要试图绕过。
